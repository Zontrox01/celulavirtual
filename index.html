Qué es Célula Virtual

Una célula virtual vacía a la que se le puede instalar un genoma real y observar su evolución temporal completa: expresión génica, regulación, metabolismo acoplado a energía y división celular, todo bajo cinética química estocástica exacta.

Célula Virtual es un software que representa una célula mínima simulada con el algoritmo de Gillespie. En lugar de utilizar reglas ad hoc, cada reacción se modela como un proceso estocástico bien definido. El sistema acepta genomas reales (FASTA + anotación) y está diseñado para escalar desde unos pocos genes hasta cientos sin cambiar código.

A diferencia de otros simuladores de biología de sistemas (E-Cell, VCell, whole-cell models de Karr/Covert Lab), el motor de simulación se ha escrito específicamente para poder inspeccionarlo por dentro mientras corre. No es una caja negra: se puede pausar, examinar el espacio de propensidades, seguir la causalidad de eventos y retroceder en el tiempo de forma reproducible.

Funcionalidades principales

Motor de simulación

El núcleo del sistema vive en engine/ y está basado en el algoritmo de Gillespie (SSA) implementado como iterador. Esto permite:

  • Simulación estocástica exacta de reacciones químicas.
  • Pausar la ejecución en cualquier punto.
  • Capturar snapshots del estado molecular.

Depurador interactivo

El módulo engine/debugger.py añade capacidades de depuración sobre el motor:

  • Ejecución paso a paso y breakpoints condicionales sobre el estado molecular.
  • Visualización en vivo del espacio de propensidades.
  • Análisis causal retrospectivo: responder preguntas como “¿qué consumió todo el ATP?”.
  • Retroceso (undo) reproducible bit a bit a estados anteriores.

Biología de la célula

Los módulos en biology/ implementan los procesos biológicos clave:

  • Transcripción, traducción y degradación de ARNm y proteínas.
  • Regulación (represión) y metabolismo acoplado a ATP.
  • División celular con reparto binomial de especies entre células hijas.

Genomas reales e interoperabilidad

La entrada de datos se gestiona en data_io/:

  • Carga de genomas reales vía FASTA + anotación CSV (genome_loader.py).
  • Diseño pensado para escalar de 5 a cientos de genes sin cambiar código.
  • Exportar e importar modelos en formato estándar SBML (sbml_io.py).

Interfaz gráfica y herramientas

La interfaz gráfica de escritorio en gui/ (PySide6, tema oscuro) expone:

  • Pestaña Genoma: carga e instalación de genomas de ejemplo.
  • Pestaña Ejecución: control de la simulación en tiempo real.
  • Pestaña Depurador: inspección detallada del motor y las propensidades.
  • Pestaña Forense: análisis retrospectivo de trayectorias y consumo de recursos.

El directorio tools/ incluye utilidades de desarrollo, como generadores de genomas sintéticos para pruebas controladas, y tests/ contiene la suite de validación.

Instalación y uso rápido

Instalación

git clone https://github.com/Zontrox01/celulavirtual/
cd celula-virtual
pip install -r requirements.txt

El proyecto requiere Python 3.10 o superior. El archivo docs/requirements.txt detalla qué librería interviene en cada fase del proyecto (motor, biología, GUI, interoperabilidad).

Interfaz gráfica

python -m gui.app

Desde la pestaña Genoma, se puede cargar examples/genomas/toy_genome.fasta y su anotación, instalar el genoma en la célula virtual y pasar a Ejecución para correr la simulación con visualización en tiempo real.

Uso desde código

from cell import Cell
from engine.reactions import Reaction

cell = Cell(seed=1)
cell.add_species("A", 100).add_species("B", 0)
cell.add_reaction(Reaction("A_to_B", {"A": 1}, {"B": 1}, rate_constant=1.0))

cell.run()
print(cell.species.get_count("B")) # 100

df = cell.get_trajectory() # pandas.DataFrame, tiempo x especie x cantidad

Depurador interactivo

debugger = cell.debug(enable_snapshots=True)
debugger.set_breakpoint("poca_A", lambda s: s["A"] < 10)
debugger.run_until_breakpoint()
print(debugger.pending_propensities()) # qué reacciones podían haber disparado
debugger.undo_to(5) # retroceder al paso 5, exactamente

Instalar un genoma real

from data_io.genome_loader import load_genome
from biology.genome import GenomeModule
from biology.translation import TranslationModule
from biology.degradation import DegradationModule

genome = load_genome("examples/genomas/toy_genome.fasta",
    "examples/genomas/toy_genome_annotation.csv")
cell = Cell(seed=1)
installed = GenomeModule(genome).install(cell)
translated = TranslationModule(installed).install(cell)
DegradationModule(installed, translated).install(cell) # sin esto, ARNm/proteína crecen sin límite

cell.run(max_steps=500)

Ejecutar los tests

pytest tests/ -v

Estructura del proyecto

La organización del repositorio refleja la separación entre motor de simulación, biología, entrada/salida de datos, interfaz gráfica y herramientas de desarrollo:

celula-virtual/ ├── engine/ # Motor de simulación (SSA, depurador, snapshots, forense, trayectorias) ├── biology/ # Módulos biológicos (genoma, transcripción, traducción, degradación, regulación, metabolismo, replicación) ├── data_io/ # Carga de genomas (FASTA + anotación) e interoperabilidad SBML ├── gui/ # Interfaz gráfica de escritorio (PySide6) ├── tools/ # Utilidades de desarrollo (generador de genomas sintéticos) ├── tests/ # Suite de tests ├── examples/ # Genomas de ejemplo ├── docs/ # Whitepaper de diseño ├── requirements.txt └── FILES.md # Mapa vivo de qué archivo hace qué y su estado

Para saber exactamente qué hace cada archivo y en qué estado está (implementado, en progreso, pendiente), el documento docs/FILES.md actúa como mapa vivo y se actualiza en cada cambio relevante.

Documentación y estado del proyecto

Documentación

  • docs/whitepaper_celula_virtual.md — diseño completo: motivación, arquitectura, decisiones y por qué se tomaron, roadmap por fases, limitaciones conocidas.
  • docs/FILES.md — tabla de control de archivos y su estado.

Estado actual

El ciclo celular central — motor SSA, depurador completo, expresión génica, regulación, metabolismo y división celular — está implementado y validado con tests. La interoperabilidad SBML también está operativa.

La interfaz gráfica está construida y pendiente de validación funcional completa en un entorno con pantalla real (ver FILES.md). El roadmap detallado, fase a fase, se encuentra en la sección 8 del whitepaper.

Limitaciones conocidas

Documentadas en detalle en la sección 12 del whitepaper. Entre las más relevantes:

  • Simulación no espacial (sin difusión ni geometría celular real).
  • Sin mutación del ADN: dinámica temporal, no evolución darwiniana (decisión deliberada, no limitación técnica).
  • Transcripción y traducción modeladas como un único paso estocástico, no como la cadena completa de unión/elongación/terminación.
  • La GUI no soporta simular varias células a la vez tras una división.
